# ATDT

A native iOS and Android reader for the [Phrack](http://phrack.org) archive, shown exactly as published: 80 columns, monospace, no reflow.

```
ATDT — the Hayes command to dial a number. Pick up the line, start reading.
```

## What it does

- Downloads the full Phrack archive to the device once, then reads it offline.
- Shows every phile as its original fixed-width text. At fit, exactly 80 columns fill the screen. Longer lines scroll sideways as one block.
- Keeps your exact reading position when you rotate the device or change fonts.
- Ships bundled fonts, including crisp, integer-scaled retro pixel fonts, plus several colour themes.
- Immersive reading: the chrome hides while you scroll and comes back with a gesture.

The app does **not** bundle any Phrack content. Text is fetched on-device from the Phrack site.

## Requirements

- [Flutter](https://docs.flutter.dev/get-started/install) 3.47.7 (stable channel), which includes Dart 3.13. CI and the golden-image tooling pin this exact version.
- JDK 17, available to `flutter doctor`, for Android builds
- Android Studio or the Android SDK, for Android builds
- Xcode on macOS, for iOS builds
- Docker, only for regenerating golden images on Windows or macOS

## Getting started

```sh
flutter pub get
flutter run
```

The app opens on the list of Phrack issues. On first launch it explains the one-time download (about 31 MB from archives.phrack.org) and starts it when you confirm; issues appear as they arrive, and an interrupted download resumes. Tap an issue for its philes, and a phile to read it.

In the reader, tap the text to show or hide the chrome. The chrome switches font (JetBrains Mono, IBM Plex Mono, BigBlue Terminal, Terminus or C64 Pro Mono), theme and orientation (Auto, Portrait, Landscape), and the bug icon shows a layout debug overlay. The settings screen (gear icon on the issues list) has the same choices, which are remembered, five built-in themes (green and amber phosphor, paper, high contrast, VGA blue) plus your own themes made with a colour picker, plus Credits with every font's licence. Characters a font cannot draw show as its `·` (or `?`) so columns never shift, and the reader offers a font that has them all. The cloud icon checks for new issues.

Phrack text is never committed to this repository or bundled in the app: the app downloads it on the device.

## Testing

```sh
flutter test                         # unit and widget tests (goldens skip on Windows/macOS)
dart run tool/gen_fixtures.dart      # regenerate the synthetic fixtures (deterministic)
```

### Ingestion over the real archive

A developer tool (not a test) runs ingestion over every Phrack issue and writes a CSV of encoding, line count, longest line and control-character counts per phile:

```sh
dart run tool/ingest_archive.dart          # all issues; or: ... 1 10
```

Issue tarballs are downloaded once (1 s apart) into the git-ignored `tool/out/archive/`; the report is `tool/out/ingest_report.csv`.

With those tarballs cached, a second tool imports the whole archive, builds the search index, and reports its size and query times:

```sh
dart run tool/search_bench.dart            # writes tool/out/search_bench.sqlite
dart run tool/sections_report.dart         # jump-list coverage, refusals and the early-era check
dart run tool/sections_report.dart 57/8    # ...plus the outline of one or more philes
```

### Adding a font

Put the font file in `assets/fonts/files/` and its licence text in `assets/fonts/licences/`, then add an entry to `assets/fonts/manifest.json`. No code or pubspec changes are needed; `test/fonts/font_manifest_test.dart` checks the entry, the files and the licence.

### Storage

The database schema lives in `lib/storage/archive_database.dart`. Generated drift code (`*.g.dart`) is committed; after changing the schema, regenerate it:

```sh
dart run build_runner build --delete-conflicting-outputs
```

The archive parser's test tarball is generated by `uv run tool/gen_archive_fixture.py` (deterministic).

### Golden images

Goldens are rendered on Linux only, because text rasterisation differs between operating systems. CI checks them. To regenerate them from Windows, with Docker running:

```powershell
pwsh tool/goldens/update.ps1          # rewrite test/reader/goldens/*.png
pwsh tool/goldens/update.ps1 -Check   # compare only, as CI does
```

On Linux, `flutter test --update-goldens` works directly.

### Device tests

Run each integration test file on its own; device runs do not handle several files at once. CI runs the launch, rotation and reading-position tests on an Android emulator and an iPhone simulator; the benchmarks need a real device. Note that `flutter test integration_test` uninstalls the app afterwards on Android, taking a downloaded archive with it. It also builds the test into `build/app/outputs/flutter-apk/app-debug.apk`, so rebuild with `flutter build apk --debug` before installing that file by hand: the test build sits on the splash screen waiting for a test harness.

```sh
flutter test integration_test/app_test.dart -d <device>
flutter test integration_test/reader_rotation_test.dart -d <device>
flutter test integration_test/storage_perf_test.dart -d <device>   # readLine < 5 ms (asserted in profile/release)
flutter test integration_test/reader_polish_test.dart -d <device>   # position across sessions, orientation
flutter test integration_test/search_perf_test.dart -d <device>   # search < 300 ms over an archive-sized index (asserted in profile/release)
```

### Scrolling performance

Profile builds run on an x86_64 emulator, but its emulated GPU makes frame times meaningless (the plain reader rasterises at about 5 fps there), so measure on a physical device:

```sh
flutter drive --profile --no-dds   --driver=test_driver/perf_driver.dart   --target=integration_test/scroll_perf_test.dart -d <device>
```

Timeline summaries are written to `build/scroll_perf_<font>.timeline_summary.json`, and `build/scroll_perf_crt.timeline_summary.json` for the default font with the CRT effect on (Stage J: 60 fps, so rasteriser times under 16.7 ms).

## Release builds

```sh
flutter build apk --release        # Android; flutter build appbundle for Play
flutter build ios --release        # needs a Mac and Xcode
```

- **Android signing:** create an upload keystore, then `android/key.properties` (git-ignored) with `storeFile`, `storePassword`, `keyAlias` and `keyPassword`. Without it, release builds are signed with the debug key. They work locally and in CI, but can't be uploaded to a store.
- **App icons** are drawn by `uv run tool/make_icon.py` into `assets/icon/` and turned into every platform size with `dart run flutter_launcher_icons`. That tool rewrites a boolean in `ios/Runner.xcodeproj/project.pbxproj` to `AppIcon`; revert that hunk afterwards.
- **Privacy:** [`docs/privacy.md`](docs/privacy.md), shown in the app under Settings → Privacy (a test keeps the two identical).
- **Manual device passes** are recorded in [`docs/test-log.md`](docs/test-log.md).

## Project layout

```
lib/
  layout/      Pure Dart layout maths (no Flutter imports)
  ingest/      Pure Dart decoding and normalisation (no Flutter imports)
  fonts/       Pure Dart font manifest and cmap coverage (no Flutter imports)
  archive/     Pure Dart archive parsing and downloading (no Flutter imports)
  search/      Pure Dart query parsing and match highlighting (no Flutter imports)
  sections/    Pure Dart section-heading parser for the jump list (no Flutter imports)
  storage/     drift database: issues, philes, text chunks, catalog, settings, search index
  download/    Download controller and archive screen
  library/     Issues (home and first launch), issue and search screens, search indexer
  reader/      The reader widget, its scroll structure, chrome, CRT effect and debug overlay
  settings/    Settings screen
assets/
  fonts/       manifest.json, files/ (fonts) and licences/ (their licence texts)
shaders/       crt.frag, the optional CRT fragment shader (Impeller only)
assets/icon/   App icon masters (generated; see Release builds)
test/
  fixtures/    Synthetic, byte-exact text fixtures
  archive/fixtures/   Synthetic issue tarball
  reader/goldens/   Golden images (Linux-rendered)
  architecture_test.dart   Fails if a pure-Dart folder imports Flutter
integration_test/   Device tests (rotation, position, orientation, storage, scroll and search performance)
test_driver/   Driver for the performance test
tool/          Developer scripts (fixtures, archive batch run, search benchmark, sections report, icon, goldens)
docs/          Spec, decisions log, spike report
```
